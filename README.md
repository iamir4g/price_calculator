# ماشین‌حساب قیمت محصول

اپلیکیشن لوکال Streamlit برای محاسبه قیمت تمام‌شده محصول روی پلتفرم‌هایی مثل **اسنپ شاپ** و **دیجی کالا**، با پشتیبانی از تنظیمات جداگانه برای هر پلتفرم، تخفیف همکار، هزینه ارسال پویا، و پردازش دسته‌ای Excel/CSV.

اجرای داخلی روی **ویندوز** و **مک** — بدون نیاز به دیپلوی وب.

## امکانات

- محاسبه لحظه‌ای قیمت تکی (ریال و تومان همزمان)
- تفکیک: قیمت لیست، تخفیف خرید، قیمت خرید، کمیسیون، زیرساخت، مالیات، ارسال (با نشان حداقل/حداکثر)، قیمت فروش در پلتفرم، سود خالص، قیمت فروش سایت
- پروفایل جدا برای هر پلتفرم (درصدها + کف/سقف ارسال) ذخیره‌شده در `data/platforms.json`
- آپلود CSV/Excel و دانلود خروجی `.xlsx`
- رابط کاربری فارسی و RTL

## پیش‌نیاز

- Python 3.10 یا بالاتر

## نصب و اجرا

### مک / لینوکس

```bash
cd price_calculator
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
streamlit run app.py
```

### ویندوز (PowerShell)

```powershell
cd price_calculator
py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

مرورگر معمولاً روی `http://localhost:8501` باز می‌شود.

## منطق محاسبه (خلاصه)

مدل مطابق فایل `snappshop_pricing.xlsx` است: ورودی «قیمت لیست» تولیدکننده است و خروجی «قیمت فروش در پلتفرم».

1. `قیمت خرید = قیمت لیست × (1 − تخفیف خرید%)`
2. `هدف = قیمت خرید × (1 + سود%)` — سود هدف نسبت به **قیمت خرید** است.
3. پلتفرم از **قیمت فروش (p)** این‌ها را کم می‌کند:
   - کمیسیون% × (1 + مالیات%)
   - هزینه زیرساخت% × (1 + مالیات%) (مالیات روی زیرساخت اختیاری است)
   - ارسال = clamp(`ارسال% × p`، کف، سقف)
4. چون ارسال خودش درصدی از p است، قیمت با **حل معکوس دقیق** به‌دست می‌آید (نه تقریب)، با `k = 1 − fee×(1+vat) − infra×(1+vat)`:
   - ارسال روی کف: `p = (هدف + کف) / k`
   - ارسال درصدی: `p = هدف / (k − ارسال%)`
   - ارسال روی سقف: `p = (هدف + سقف) / k`
5. قیمت فروش رو به بالا به مضرب `rounding_toman` (پیش‌فرض ۱٬۰۰۰ تومان) گرد می‌شود و سود واقعی از روی قیمت گردشده دوباره محاسبه می‌شود.
6. `قیمت فروش سایت = قیمت خرید × (1 + مارک‌آپ سایت%)` (جدا از پلتفرم)

تبدیل واحد: **۱ تومان = ۱۰ ریال**

### فروش باندل
چند عدد از یک کالا در **یک سفارش**: سود هدف به نسبت تعداد زیاد می‌شود ولی هزینه ارسال فقط یک‌بار (با همان کف/سقف) حساب می‌شود. خروجی: مبلغ کل باندل، قیمت هر عدد در باندل، کاهش قیمت هر عدد نسبت به فروش تکی، و حداقل تعداد برای رسیدن به سقف ارسال. تعداد پیش‌فرض (`bundle_quantity`) در تنظیمات هر پلتفرم است و در تب ماشین‌حساب و دسته‌ای قابل تغییر است.

### پردازش دسته‌ای
اگر فایل ستونی با نامی شامل «کمیسیون» یا «زیرساخت» داشته باشد (درصد، مثلاً `9` یا `0.6`)، برای هر ردیف به‌جای مقدار پیش‌فرض پلتفرم استفاده می‌شود. این برای دسته‌هایی مثل چراغ خواب (۱۱٪) یا چندراهی برق (زیرساخت ۰٫۷٪) لازم است.
